# 🤖 Avito Intern Test — Детекция ботов по cookie-логам

Репозиторий содержит решение тестового задания для стажировки в Авито. Задача заключается в автоматическом выявлении ботов среди пользователей (`cookie_id`) на основе последовательности их действий (событий) на платформе.

---

## 📌 Постановка задачи и метрика

* **Целевая переменная:** Бинарный флаг бота (`target` в `train.csv`). Доля ботов в обучающей выборке составляет около 8.1%.
* **Официальная метрика кейса:** Precision при Recall >= 0.70.
* **Особенности расчета (`metric.py`):**
  1. Куки сортируются по убыванию предсказанного `score`.
  2. Одинаковые значения `score` обрабатываются **единой группой** (нельзя разделить куки с равным скором: либо отмечены все, либо никто).
  3. Итоговая метрика — **максимальный precision** на всей области порогов, где Recall >= 0.70.

---

## 🛠 Используемый стек

* **Python 3.10+**
* **Pandas / NumPy** — эффективная обработка табличных данных и логов.
* **CatBoost** — градиентный бустинг для бинарной классификации.

## 🔍 Детальное описание решения

### 1. Предобработка и фильтрация данных
* **Временные окна:** События из таблицы `events.csv.gz` фильтруются строго по временному окну (`event_ts` находится между `window_start_ts` и `window_end_ts`) для каждой куки. Это позволяет исключить шум, не относящийся к целевому периоду оценки.
* **Нормализация платформ:** Поле `platform` приведено к нижнему регистру, а разрозненные варианты написания (`iphone`, `iOS`, `ios`) унифицированы для корректного группирования.
* **Маппинг событий:** Исходные названия событий (`event_name`) заменены на числовые коды (`eid`), что удобно для анализа поведенческих паттернов.

### 2. Инженерия признаков (Feature Engineering)
В репозитории реализован ряд сильных поведенческих признаков, разделяющих активность людей и автоматизированных скриптов:
* **Анализ дубликатов:** Удаление полных дубликатов строк с созданием признака `cnt_duplicate` (гипотеза: боты часто отправляют идентичные запросы с фиксированной периодичностью, в то время как пользователи могут кликать повторно при зависании интерфейса).
* **Агрегации по сессиям и событиям:** 
  * Частота и интенсивность различных типов действий (`search_results_view`, `item_view`, `contact_phone_show`, `favorite_add` и др.).
  * Статистика по используемым устройствам, категориям товаров (`item_category`), регионам (`item_location`) и поисковым запросам.
  * Анализ координат кликов (`pointer_x`, `pointer_y`) — у ботов эти признаки часто имеют аномальные распределения или полностью пропущены.

### 3. Обучение модели и валидация
* **Модель:** В качестве основного классификатора используется `CatBoostClassifier`, устойчивый к категориальным признакам и выбросам.
* **Стратегия валидации (Time-based Split):** Вместо случайной кросс-валидации используется разбиение по временным окнам (`window_start_ts`). Модель обучается на исторических данных и проверяется на более свежих (будущих) периодах. Это полностью исключает утечку данных (data leakage) и имитирует реальные условия проверки на платформе.
* **Контроль качества:** Для оценки результатов локально используется официальный скрипт `metric.py`, считающий целевой `precision_at_recall`.
